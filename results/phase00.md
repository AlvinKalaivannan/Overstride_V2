## Gate verdict

The gate reads: *"`docs/data-inventory.md` exists and Table 1 reproduces."*

The file exists. "Table 1 reproduces" is binary and the result is not, so the
judgment is recorded here rather than asserted:

- **36 of 56 cells reproduce** exactly (counts exact, means to 0.01).
- **Every male/female subject count reproduces** except `No Injury (age 50+)`
  (49 → 48), and **5 of 7 session counts** are exact — including osteoarthritis
  at 247 subjects / 422 sessions.
- **2 of 7 groups reproduce on all six subject and session counts**
  (`achilles tendonitis`, `plantar fasciitis`).
- The residual misses are two systematic effects, not scatter: speeds sit
  0.005–0.07 m/s low in nearly every group (the paper appears to average over
  all sessions, not first-session-per-subject), and `No Injury (age 50+)` misses
  on every field because the age-50 boundary is evaluated against a different
  session than the one taken as first.

**Called met** because cohort *construction* — who is in which group, and how
many sessions they contribute — reproduces. That is what phase 1 depends on.
The failures are in summary statistics, and their causes are identified rather
than unexplained. Cell-by-cell table: `docs/data-inventory.md` §4.

## Deviation from the spec

**A recorded diagnosis was treated as outranking a blank severity.** The
dataset README defines uninjured as `InjDefn` = 'No injury' **and** `InjJoint` ∈
{'No injury', blank} **and** `SpecInjury` blank. Applied literally, 352
osteoarthritis sessions — real `SpecInjury`, blank `InjDefn` — fall into neither
class and the entire OA cohort disappears from Table 1 (70 sessions instead of
422). Under the diagnosis-outranks-blank-severity rule, OA reproduces exactly
and the overall score rises from 28/56 to 36/56.

This is a labelling decision, not a formatting one, and it is load-bearing:
applied the other way it silently drops ~20% of injured sessions. Recorded here
so it is auditable. Also in `docs/data-inventory.md` §4 and
`docs/ferber-schema.md` trap 2.

## What surprised us, or looks wrong

1. **The waveforms are not in the archive.** The JSONs hold raw marker
   trajectories plus 76 *scalar* descriptive variables per side — nothing
   time-normalized. The 100-point curves are an *output* of the bundled MATLAB
   pipeline, which has not been run. Phase 1 cannot start by loading an array.
2. **They are 101 points, not 100** — `gait_steps.m:676` allocates
   `zeros(101, n_steps, 3)`. `CLAUDE.md` §Conventions was wrong and is corrected.
3. **`Height = 999` is a missing-data sentinel, and it contaminated the
   published Table 1.** The Achilles tendonitis 190.19 cm the spec flagged as a
   probable transcription error reproduces *exactly* — the paper is faithful to
   the file. One `999` among ~50 subjects moves the mean ~16 cm; masked, the real
   mean is 174.33 cm. Treat every published group mean involving `Height` as
   contaminated.
4. **The `999` sentinel is in four columns, not one** (found while scoping phase
   1, folded back into the inventory). `age` carries a `255`, `Weight` a `1564`
   and two `0`s, `Height` three `0`s, and **`YrsRunning` 51 rows of `999`** —
   51 sessions claiming 999 years of running experience. Every one is a feature
   of the demographics-only control. Only `Height` was caught on the first pass,
   because only `Height` was checked; the others were found by sweeping all five
   numeric control features against plausible physiological ranges.
5. **Metadata missingness leaks the label, and it is a collection artifact.**
   Whether a questionnaire field was filled in tracks the study wave, and the
   waves differ in injury mix. A blank `Level` marks an uninjured session with
   **95.0% precision**; `lvl_missing` alone scores **AUC 0.660** while measuring
   nothing but paperwork. The 2017 wave is 51 sessions / 17 subjects, entirely
   uninjured, with a completely blank questionnaire. Complete-case analysis is
   not an escape — it deletes 45% of the uninjured class. This forces a
   provenance-only baseline into every phase; see `docs/phase1-spec.md`.
6. **The two 1,402s are a coincidence.** The paper reports 1,402 subjects
   injured at testing, and separately 112 + 1,290 = 1,402 subjects with running
   data. The run metadata does hold exactly 1,402 subjects — split 988 / 363 / 71,
   not 1,402 / 0. "Has running data" is not a proxy for "injured".
7. **Osteoarthritis barely exists in the running data** — 247 subjects overall,
   but only **12** ran, over 14 sessions. The `CLAUDE.md` exclusion rule costs
   almost nothing, and a separate OA kinematic analysis is not viable at that n.
8. **The two largest "diagnoses" are `pain` (232 sessions) and `other` (184).**
   416 sessions of non-diagnosis. The usable label set is much smaller than the
   injured-session count suggests.
9. **The archive is Deflate64.** Python `zipfile`, .NET `System.IO.Compression`
   and libarchive 3.8 all fail on it. The Windows shell zip handler works —
   `scripts/extract_ric_data.ps1`.
10. **Sampling-rate scan cross-validates the metadata exactly.** Files with
   running data = 1,832 (matches `run_data_meta.csv`); with walking = 2,088
   (matches `walk_data_meta.csv`); 2,506 total. Running is 200 Hz for all but 10
   sessions.

## Reproduction

```
.venv/Scripts/python.exe scripts/phase0_inventory.py
```

Requires `DATA_ROOT` in `.env`. Reads `$DATA_ROOT` read-only; opens session
JSONs one at a time (peak working set 340 MB against 48.25 GB on disk). Takes
~30 s.

**Determinism:** output is byte-identical across runs apart from two measured
timing values (mean parse time per file, and the full-corpus header-scan
duration). No sampling is randomized — the 20 profiled files are selected
deterministically across injury groups.

## Constraints honoured

- `$DATA_ROOT` read from the environment, never hardcoded; never written to.
- No session JSONs accumulated in memory; 20 sampled for structure, then a
  4 KB head-scan for the full 2,506.
- Nothing synthesized. No parse failures to report — every sampled file was
  valid JSON.
- No modelling, features, classifiers, splits or plots.

## Blocking phase 1

**Generating the waveforms from raw markers is unscoped and is a prerequisite.**
The target array is `(1832, 9, 101)` float32 — 6.7 MB — but it must be *computed*
from 48 GB of trajectories by running the bundled MATLAB pipeline (MATLAB R2026a
is installed locally; the code targets R2023a) or a faithful Python
reimplementation. This needs a spec of its own before phase 1 begins.
